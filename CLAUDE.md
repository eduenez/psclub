# CLAUDE.md

Context for anyone (human or Claude Code) working on this repository.

## What this is

The site of the Mathematics Problem-Solving Club at The University of Texas at
San Antonio. It exists because the club's only public presence was three
sentences on a university CMS page that cannot hold a sign-up form, a PDF, or a
meeting time, and that changes only by IT ticket.

The site is user-owned and user-controlled. The design goal is that changing the
meeting time takes one edit and requires nobody's permission — including on the
official UTSA page, which frames `/embed/` from here.

Sibling site, same reasoning, same conventions:
`~/repos/utsa-quantum-math.github.io`. Read its CLAUDE.md before making
structural changes here.

## The one rule

**No roster, ever.** The club mailing list is 100+ student names and addresses.
It is FERPA-sensitive, it lives only in the private `teaching` repo, and git
history is permanent. `bin/check-pii.sh` runs first in CI and fails the build on
a student address, a roster-shaped filename, or the banner described below.

Run it before you push. It has been verified to catch planted violations.

## Stack

- Jekyll 4.3 built by GitHub Actions (`.github/workflows/build.yml`), not the
  legacy Pages builder. Deployed to `https://supernumero.us/psclub/`, a project
  site under the user site's custom domain.
- No theme gem. Layouts and CSS are ours. Deliberately **not** `just-the-docs`
  — that is what the sibling `courses` site uses, and it is a documentation
  sidebar theme, wrong for a club landing page.
- `Gemfile.lock` is committed. `csv`, `base64`, `bigdecimal` and `logger` are
  pinned because Ruby 3.4 dropped them from the standard library and Jekyll 4.3
  still expects them.
- KaTeX from a CDN, `\(`…`\)` delimiters only. A bare `$` is **not** a
  delimiter: enabling it would turn any stray dollar sign in prose into math.

## Data, not pages

Two data files drive everything. Nothing is hand-written twice.

**`_data/club.yml`** — every fact that changes without the structure changing:
meeting day/time/room, term, contact, and the mailing list. `index.md`,
`join.md` and `embed.md` all read it, and `_includes/meeting.html` is the single
renderer of the meeting line, so those three pages cannot disagree.

Because the official UTSA page frames `/embed/`, **editing `club.yml` is what
updates the university's page.** That is the whole point of the arrangement.

**`_data/sets.yml`** — GENERATED by `bin/extract-problems.py`; do not hand-edit.
Every problem in the LaTeX sources is already a structured record:

```latex
\begin{challenge}{Title}{Topic / Difficulty}{Source}
```

The script reads those back out. Some sets suppress fields 2 and 3 in the
rendered PDF, but the metadata is in the source either way, which is how the
site shows a hint layer without publishing solutions.

## Adding a problem set

1. Add the `.tex` to the `SETS` table in `bin/extract-problems.py` **and** to
   the `SETS` array in `bin/sync-sets.sh`. The two must agree; `bin/check-build.sh`
   fails if a set has data but no PDF, or a PDF but no data.
2. `python3 bin/extract-problems.py`
3. `./bin/sync-sets.sh <slug>`
4. Add `problems/<slug>.md` — a five-line stub naming the slug; the `set` layout
   renders everything from the data.

## Conventions that are easy to violate

**The sources are not in this repo.** The `.tex` files live in
`~/repos/teaching/ProblemSolving/ProblemSetsPSC` (private) and stay the single
source of truth; this repo holds only built artifacts. Override the location
with `PSC_SRC`. Note `teaching/.gitignore` excludes `*.pdf` repo-wide, so the
PDFs could not live beside their sources even if you wanted them to.

**Compile in a scratch directory, never in the source tree.** `bin/sync-sets.sh`
applies filters before compiling — it strips solutions and downsamples banners
— and must not mutate the sources.

**Problems and hints, no solutions.** `bin/sync-sets.sh` strips
`\begin{solution}`…`\end{solution}` at build time. Only
`UTSA_PSC_favorites.tex` currently has one.

**Commented-out problems stay out.** Several sets keep problems in reserve
behind a leading `%`, either duplicates of another set or held for a future
meeting. `uncommented()` in the extractor blanks those lines. Nine problems are
currently withheld this way; the site shows 84, not 93.

**`GamesStrategy.png` must never be published.** The artwork has
AI-generation artifacts rendered into it — about a dozen literal `[cite: 6, 7]`
strings and the garbled captions "Scored m x n beak" and "Pluck owe petals".
They are raster, not text, so no text search finds them; the only guard is that
the image is not embedded anywhere. `sync-sets.sh` drops the banner from the
Games set and `check-pii.sh` proves it stayed dropped. Delete both blocks once
the image is regenerated.

**No UTSA logo, wordmark, or Roadrunner. Palette only.** The "UTSA MathPSC"
mark in the lower right of `five-minute-gems.png` is the university's own
registered wordmark and is deliberately not reused; the favicon is a Halmos
tombstone on burgundy instead. The footer disclaimer stating that this is not an
official University publication stays.

**Run the checks under CI's Ruby, not yours.** `.github/workflows/build.yml`
pins Ruby 3.3; a newer local Ruby will pass things CI rejects. This has already
bitten once: `check-build.sh` reads `_data/sets.yml` with
`permitted_classes: [Date]`, and Ruby 4 happens to have `Date` loaded while 3.3
does not, so the check died in CI with `uninitialized constant Date` -- and the
empty result made all seven PDFs look orphaned, hiding the real cause. Fixed
three ways: `-rdate` is now explicit, dates in the generated YAML are quoted so
no `Date` object is produced at all, and an empty set list is treated as a
broken check rather than a passing one. To reproduce CI locally:

```
RBENV_VERSION=3.3.12 PATH="$HOME/.rbenv/shims:$PATH" ./bin/check-build.sh
```

**A check never writes to what it checks.** The staleness check regenerates to
a temp file and diffs. An earlier version ran `git checkout -- _data/sets.yml`
to clean up after itself and silently reverted real edits.

**Burgundy `#800020` is not arbitrary.** It is `themecolor` from the problem-set
LaTeX preambles, where the comment reads "Burgundy for 'Math Club' feel", so the
site and the PDFs students already hold read as one thing.

**Banners are quantized, not just resized.** They are near-monochrome line art
stored as truecolor PNG. `-colors 64` takes the seven PDFs from 12 MB to 2.1 MB
with no visible loss. Resizing alone gets nowhere near that.

## Known rough edges

- The Fall 2026 meeting day, time and room in `_data/club.yml` are
  placeholders, with `tba: true` so the site says so rather than asserting a
  wrong time. **Set these before announcing the site.**
- The mailing list currently points at a Google Group.
  `math-psclub@utsa.edu` has been requested from UTS. If it arrives as an
  Exchange distribution list it will have no self-subscribe page and no
  confirmation loop, in which case the Google Group stays the subscription
  front end and the UTSA address becomes the sending address. Set
  `list.self_subscribe: false` and `join.md` switches to the mailto: path on
  its own.
- `LA_alt.tex` (14 problems, three tiers) is an unpublished alternative to
  `LinAlgProblems.tex` (10). Publish one, not both.
- `alternate.tex` is excluded permanently: it duplicates the Spring 2026 set
  and does not compile (it wants a `math_club_banner.png` that does not exist).
- No meetings collection and no calendar feed. If the club starts keeping a
  schedule, model a meeting as a record and copy the `_talks/` design from the
  quantum mathematics site rather than hand-writing a listing.

## Non-goals

Anything that reintroduces a gatekeeper. If a proposed feature means a change
has to wait on a person, it is the wrong feature.
